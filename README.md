# SAQ — Возражения

Тестовый модуль ДВГА с тремя исходными обращениями: на уведомление, аудиторский отчёт и акт профилактического контроля.

Сайт: https://saq-objections-test.vercel.app/

Репозиторий: https://github.com/ewgftju/ewgftju-saq-objections-test

## Структура как в проекте команды

Подход сопоставлен с `ewgftju/saq-prof-control-demo`, ветка `main`, снимок дерева `48b2426042aafc28753d1ad9cf8d3b62103774fa`.

- `frontend/` — React 19, TypeScript в strict-режиме, Vite 7.
- `frontend/src/components/` — общие элементы интерфейса и шапка SAQ.
- `frontend/src/modules/objections/` — модуль, страницы, формы, маршруты, модель и сервисы процесса.
- `frontend/src/api/objectionsRepository.ts` — изолированный адаптер хранения демо.
- `frontend/src/types.ts` — типы карточек, пунктов, ролей, решений и документов.
- `frontend/src/data/` — тестовые обращения и справочники.
- `frontend/src/modules/objections/tests/` — проверки предметной логики и React-разметки.
- `docs/` — нормативная модель, архитектура и сценарий показа.

Интерфейс сохранён в стиле `saq-prof-test`: палитра, шапка, боковая навигация, кнопки и карточки. Шрифт Roboto включён в сборку, без зависимости от внешнего сервиса шрифтов.

Это frontend-прототип. Django/DRF и PostgreSQL из референсного проекта сюда не скопированы: серверная часть и интеграции в этой версии не реализованы.

## Запуск и проверка

Нужен Node.js 20.19+ или 22.12+.

```sh
npm --prefix frontend ci
npm run dev
npm run typecheck
npm test
npm run build
```

В Windows при необходимости используйте `npm.cmd`.

## Основные маршруты

- `/cases` — реестр обращений.
- `/cases/:id/overview` — карточка.
- `/cases/:id/review` — рассмотрение по доводам.
- `/cases/:id/documents` — документы.
- `/cases/:id/history` — журнал действий.
- `/sessions` — заседания комиссии.
- `/processes` — бизнес-процессы.
- `/sources` — нормативная база и статус проверки.

Прямые ссылки работают через SPA-переадресацию в `vercel.json`.

## Подача обращения из кабинета объекта №2

В реестре кабинета «Объект №2» доступна кнопка «Подать обращение». Заявитель выбирает вопросы исходного отчёта и по каждому вводит довод в поле «Обстоятельства, на которые объект государственного аудита, подающий возражение, основывает свои требования, и доказательства, подтверждающие эти обстоятельства». Общее поле обстоятельств убрано; отдельного поля «Обоснование» нет. «Перечень прилагаемых документов» — текстовое поле, которое заявитель заполняет вручную. В этом разделе загрузки файлов нет; подтверждающие документы прикрепляются по отдельным оспариваемым вопросам. Введённый перечень сохраняется в черновике и поданной форме, отображается в предпросмотре и при печати. Старые поданные формы сохраняют свой состав полей.

Незавершённую форму можно сохранить в черновик; до отправки номер обращения не присваивается. После демонстрационного подписания создаётся входящее обращение для директора ДАВГА. Объекту доступна сохранённая копия поданного документа с приложениями, скачиванием HTML и печатью/PDF. Исходный отчёт и поданная версия остаются неизменными.

В этом макете `subjectAuditReports` в `frontend/src/modules/objections/services/subjectAppeals.ts` служит адаптером: доступные отчёты, сведения объекта и пункты берутся из исходных тестовых карточек соответствующего кабинета без внутренних материалов рассмотрения. Для рабочей системы источник отчётов необходимо заменить API ВГА, реквизиты заявителя получать из профиля кабинета, а демонстрационное подписание — из сервиса ЭЦП. Черновики и поданные обращения используют существующее хранилище макета.

Источником оспариваемых вопросов служит раздел результатов аудиторского отчёта. Результат вопроса передаётся как `auditProgramResult` с исходным языком и имеющимися переводами:

| Поле аудиторского отчёта ВГА | Поле обращения |
| --- | --- |
| Номер вопроса программы аудита | Номер оспариваемого вопроса |
| Наименование вопроса программы аудита | Описание оспариваемого вопроса |
| Ответ на вопрос программы аудита | Нарушение, по которому поступило возражение |

Номер, описание и нарушение подставляются автоматически; заявитель выбирает вопросы и вводит свои доводы. Ответ из отчёта хранится отдельно от доказательств и ответов органа аудита на запросы. Он сохраняется в поданной версии и используется в приложении к запросу. Если исходный ответ не передан, название вопроса и имя файла вместо него не подставляются. Старые поданные формы не пересоздаются.

В отчёте № 1-АО от 05.09.2026 для «Audit plus #1» доступны два тестовых результата: № 1 «Представительские расходы» и № 2 «Контроль приобретения, хранение и списание продуктов питания, медикаментов и мягкого инвентаря в сфере образования» с тестовыми ответами. Они добавлены в адаптер исходного отчёта (`data/subjectAuditReportResults.ts`) и доступны также при загрузке сохранённого состояния. Существующие обращения и поданные снимки не изменяются. При наличии переданных результатов ВГА используются они.

## Границы демонстрации

Данные и вложения сохраняются в localStorage браузера; серверной авторизации нет. Роли переключаются в шапке. Все организации, БИН и обстоятельства вымышлены. ЭЦП, СЭД, портал закупок, аудиозапись и судебные системы имитируются. Максимальный файл — 2 МБ. Демо-календарь ограничен сентябрём–декабрём 2026 года.

Дата отправки результата и дата вручения фиксируются разными действиями. Печатные документы сохраняют снимок данных на момент формирования.

Полная проверка всех актуальных официальных редакций НПА ещё не завершена. Дополнительно сопоставлены доступные тексты изменений № 282 и № 523 за 2026 год. Маршрут профконтроля и утверждённые формы требуют согласования с ДВГА. Подробности — `docs/business-processes.md` и `docs/demo-readiness.md`.
